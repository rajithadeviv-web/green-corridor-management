# AI-Based Green Corridor Management for Emergency Vehicles

A functional, software-only prototype built for Smart India Hackathon (SIH).
It simulates an intelligent command center that predicts traffic congestion
with a real trained ML model, scores multiple candidate routes, and
coordinates a **simulated** "green corridor" of traffic signal priority for
an emergency vehicle — recalculating everything live when a traffic event
occurs.

> **This is a software simulation.** No physical traffic signal hardware,
> live GPS, or real government traffic data is used or controlled. The UI
> displays `SIMULATION MODE — NO PHYSICAL SIGNALS CONNECTED` at all times.
> The architecture is modular so real GPS/IoT/traffic-controller integrations
> could be added later (see "Future Real-World Integration" below).

---

## 1. What's actually real here

- **Real ML model**: a `RandomForestClassifier` (scikit-learn) trained on a
  synthetic/demo traffic dataset (`data/traffic_data.csv`, clearly labeled as
  prototype data). It is trained once (`model/train_model.py`), saved to disk
  (`model/traffic_model.pkl`), and loaded once when Flask starts — it is
  **not** retrained per request, and every prediction shown in the UI is a
  live call to this model, not a hardcoded string.
- **Real route scoring**: routes are generated by traversing a simulated
  road-network graph (`data/road_network.json`) and scored with a
  configurable weighted formula (travel time, congestion, distance, signal
  delay) — the shortest route is not automatically the "best" route.
- **Real corridor/state logic**: signal states are computed and stored in
  SQLite as the simulated vehicle advances; nothing is faked in the frontend.
- **Real dynamic recalculation**: triggering a traffic event actually blocks
  or degrades edges in the graph and re-runs route optimization + corridor
  activation.

## 4. Setup (Windows / PowerShell)

```powershell
# 1. Create and activate a virtual environment
python -m venv venv
venv\Scripts\Activate.ps1

# 2. Install dependencies
pip install -r requirements.txt

# 3. Generate the synthetic training dataset
cd data
python generate_traffic_data.py
cd ..

# 4. Train the ML model (creates model/*.pkl and model_metrics.json)
cd model
python train_model.py
cd ..

# 5. Run the tests (optional but recommended)
python -m unittest discover -s tests -v

# 6. Start the application
python app.py
```

Then open **http://127.0.0.1:5000** in Chrome or Edge.

### macOS / Linux
Same steps, but activate the venv with `source venv/bin/activate` and use
`python3` instead of `python`.

## 5. Using the demo

Click **"▶ Run Full Demo Scenario"** on the dashboard. This automatically:

1. Creates a critical-priority ambulance request (City Hospital → Emergency Care Center)
2. Runs a live AI congestion prediction
3. Calculates and scores multiple candidate routes
4. Activates the green corridor on the best-scoring route
5. Lets you click **"Advance Vehicle →"** to step the vehicle through junctions
   (each junction's signal releases back to normal as the vehicle passes)
6. Lets you click **"⚠ Simulate Traffic Event"** to introduce an accident/
   blockage/congestion spike, which re-runs AI prediction, re-scores routes,
   and re-activates the corridor on the new best route
7. Lets you click **"✓ Complete & Release Corridor"** to end the trip and
   restore normal traffic, updating the dashboard stats

You can also fill in the form manually with a different vehicle type,
source/destination, and priority level.

## 6. REST API

| Method | Endpoint | Purpose |
|--------|----------|---------|
| POST | `/api/emergency/create` | Create a new emergency request |
| GET  | `/api/emergency/active` | List active requests |
| GET  | `/api/emergency/<id>` | Get one request |
| POST | `/api/traffic/predict` | Run live ML congestion prediction |
| POST | `/api/routes/calculate` | Generate + score candidate routes |
| GET  | `/api/routes/<id>` | Get saved routes for a request |
| POST | `/api/corridor/activate` | Activate green corridor on a route |
| POST | `/api/corridor/release` | Release corridor, restore normal traffic |
| GET  | `/api/corridor/status/<id>` | Get current signal states |
| POST | `/api/corridor/recalculate` | Re-run optimization after a traffic event |
| POST | `/api/traffic/event` | Simulate accident/blockage/congestion |
| POST | `/api/traffic/event/reset` | Clear simulated events |
| POST | `/api/vehicle/simulate` | Advance the simulated vehicle one step |
| GET  | `/api/dashboard` | Summary stats + model status |
| GET  | `/api/network` | Simulated road network graph |

## 7. Model evaluation

The trained model achieves (on the held-out 20% test split of the synthetic
dataset — see `model/model_metrics.json` for full numbers including the
confusion matrix and per-feature importances):

- Accuracy: ~0.84
- Precision (macro): ~0.81
- Recall (macro): ~0.84
- F1 (macro): ~0.83

These numbers describe performance on **synthetic/demo data**, meant to
demonstrate a working ML pipeline, not real-world traffic accuracy.

## 8. Currently implemented vs. future real-world integration

**Implemented in this prototype:**
AI traffic prediction, synthetic demo dataset + training pipeline, route
optimization with configurable weighted scoring, emergency request
management, green corridor signal simulation, emergency vehicle movement
simulation, dynamic traffic-event recalculation, SQLite persistence,
command-center dashboard.

**Not implemented (future work only):**
GPS tracking, live government/municipal traffic APIs, CCTV computer vision,
IoT traffic sensors, real physical traffic signal controllers, V2X
communication. The modular service structure (`services/`) is designed so
each of these could be added later without rewriting the core logic.

## 9. Notes for SIH presentation

- Innovation: coordinated multi-junction corridor logic instead of
  independent per-signal control.
- Feasibility: modular Flask + scikit-learn + graph-based route optimizer,
  all running locally with no paid APIs required for the demo.
- Scalability: swap `data/road_network.json` for a real map API and
  `services/traffic_predictor.py`'s input source for a live feed without
  touching the corridor or route-scoring logic.
